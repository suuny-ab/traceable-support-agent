# ADR-0004：绿色主线自动排队，生产切换人工批准

> 状态：已被 `ADR-0005` 取代
> 日期：`2026-07-23`

## 背景

首次唯一权威仓库部署使用手动 `workflow_dispatch`，需要人工寻找并输入成功发布运行的 ID。这个边界适合首次迁移，但会把版本选择等机械工作交给用户，并让正常发布依赖额外的命令行联网动作。

## 决定

`main` 的 `ci-release` 全部成功后，部署工作流自动取得该次运行 ID 并进入 GitHub `production` environment 队列。PR、失败 CI、非 `main` push 和其他仓库来源必须失败关闭。生产环境在部署读取 secrets 或连接服务器前要求用户点击一次 `Approve and deploy`；手动调度仅作为恢复入口，并经过同一个审批门。

自动路径把发布清单精确绑定到触发运行的 ID、Git SHA 和运行尝试号；手动恢复路径至少绑定用户选择的运行 ID。镜像摘要、`main` 祖先关系、并发锁、健康检查和失败回滚合同保持不变。该决定不启用 Provider，也不构成任何一次具体部署的授权。

## 后果

用户每次生产发布只决定是否批准已经固定的绿色版本，不再复制运行 ID 或执行服务器命令。运行名称显示来源 `ci-release` 运行 ID；并发锁不取消已开始或等待批准的部署，但只保留一个额外待处理候选。生产部署仍与代码合并、镜像发布和破坏性清理分离。完全无人批准的生产切换不在本决定范围内；只有新的明确决定和相应风险复核才能改变该边界。
