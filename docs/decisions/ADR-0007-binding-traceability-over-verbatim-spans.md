# ADR-0007：生成门从逐字锚定改为绑定式溯源

> 状态：已采纳为开发边界
>
> 日期：`2026-07-29`

## 背景

ADR-0006 确立了"LLM 负责语义对应、宿主只做机械验证"的分工，但当时落地的机械验证里
仍包含三类逐字相等检查：claim 的 `exact_span_text` 必须逐字包含于证据原文、且必须逐字
落在义务批准的 `approved_source_span` 内、`customer_visible_span_text` 必须逐字包含于
客户可见文本。

2026-07-29 本地真实 Provider（DeepSeek，authorized_real 传输）验证发现：真实模型输出
**100% 被生成门拦下转人工**（两次真实 QA 分别失败于 `top10_v6_content_invalid` 与
`top10_v8_clause_binding_invalid`）。根因是范畴错误：这些检查把"语义忠实"误作"字符串
相等"。真实 LLM 即使引用了正确的证据、表达了正确的主张，措辞也几乎不可能逐字复现原文
（标点全半角、语序、概括改写都会触发拒绝）。逐字规则没有抓住想防的风险（伪造出处），
却系统性地拦截了正确输出。

## 决定

生成门（QA `validate_result` 与工单 `validate_ticket_result_v2`，含共用的完整性门）
改为**绑定式溯源**：

砍掉逐字相等要求：

- 不再要求 `exact_span_text` 逐字包含于证据原文或批准 span；该字段保留在 schema 中，
  语义改为"关联证据的定位提示"，供人工复核快速定位。
- 不再要求 `customer_visible_span_text` 逐字包含于客户文本；语义改为"表达该主张的
  片段声明"。
- 删除逐字 clause 绑定检查（原 `top10_v8_clause_binding_invalid` /
  `ticket_v4_clause_binding_invalid`）；completeness gate 的覆盖判据从"span 逐字在
  正文中"改为"义务存在绑定的 claim"。

保留并收紧绑定存在性硬校验（可追溯底线，伪造仍失败关闭）：

- 每条 claim 必须引用至少一个证据 ID 与至少一个义务 ID；
- 引用的 ID 必须在本次检索证据集合 / 已审定义务集合中真实存在；
- 绑定不得越过义务的批准来源范围；
- 每项义务至少由一条 claim 支撑。

结构完整性校验（schema 形状、身份、长度上限、内部话术黑名单、
`insufficient_evidence` 诚实转人工）全部保留。输出 schema 不变
（`retrieved-top10-qa-result-v4` / `ticket-proposal-result-v3`）。卖点语义变为：
**每条结论都挂着真实存在的出处，证据原文随回答展示、随时可查**。

Prompt 与门同步改写（契约必须与门一致，否则发给模型的规则是谎言）：
QA prompt v8→v9，工单 prompt 新增版本常量 `ticket-proposal-prompt-v2`（此前未编号，
v1 即逐字版）。未增加任何重试或 prompt 强化逻辑。

本决定细化 ADR-0006 的跨度验证部分：ADR-0006 中"两个跨度分别真实存在于来源和客户
文本""来源跨度逐字位于批准范围"两条机械验证被本决定移除，其余分工原则不变。

## 验证

- 单元与端到端测试：断言旧逐字语义的测试改写为断言新绑定语义（措辞漂移放行、伪造
  ID 照拒、绑定越源照拒、义务缺绑定照拒），无删测试凑绿；`pytest` 130 全绿。
- 本地真实 Provider 复测：过门率从 0/2 提升到 3/3（两条 QA + 一条工单均
  `completed`/candidate，证据原文随回答挂载展示），真实调用在预算上限内。

## 后果与遗留风险

- 真实输出可以过门，候选仍只供人工批准；绑定语义不能触发业务动作。
- 遗留风险：宿主不再拦截"claim 引用了被第一阶段忽略子句"这类语义漂移（原逐字检查
  能拦一部分）。兜底为第一阶段的分区合同（每个 clause 必须显式记账为义务或忽略）与
  人工 approve 环节；公网初期应观察 handoff 分类分布，若语义漂移实际发生，再议是否
  加回语义级守卫。
- 宿主依然不做开放域语义等价判断；可追溯性的含义是"出处真实存在且可查"，不是"结论
  必然正确"。
