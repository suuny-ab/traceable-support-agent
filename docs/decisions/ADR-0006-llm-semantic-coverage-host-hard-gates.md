# ADR-0006：LLM 语义覆盖与宿主硬门分工

> 状态：已采纳为开发边界
>
> 日期：`2026-07-24`

## 背景

两阶段生成先由 LLM 选择来源义务，再生成客户可见回答或工单草稿。旧 completeness gate
要求客户文本逐字包含第一阶段选择的 `key_elements`。同一冻结候选和同一公开合成案例
分别出现一次失败、一次通过，说明这项规则会把自然改写波动当作语义遗漏；继续增加逐字
规则或机械补字会让宿主冒充语义判断，并降低客户文本质量。

## 决定

每条第二阶段 claim 同时包含：

- 来源中的逐字连续 `exact_span_text`；
- 客户文本中表达该来源主张的逐字连续 `customer_visible_span_text`；
- 已审定的来源 ID 与义务 ID。

LLM 负责判断来源主张与客户表达之间的语义对应。宿主不判断开放域语义等价，只机械验证：

- 两个跨度分别真实存在于来源和客户文本；
- 来源属于该义务的已审定来源集合；
- 每项义务至少有一条客户可见 claim；
- schema、身份、预算、隐私、安全、型号、Provider 信封和人工批准边界继续失败关闭。

候选仍只供人工批准；语义映射不能触发业务动作，也不能覆盖确定性硬门。

## 后果

合法的客户化改写不再因为缺少来源逐字片段而转人工，同时伪造客户跨度、错误来源和漏义务
仍会被宿主拒绝。该边界承认 LLM 语义判断可能出错，因此不形成开放域真实性保证，仍需要
人工语义审核和外部 API 证据。
