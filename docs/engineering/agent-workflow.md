# Agent 开发协作

本文件只规定 Agent 在本仓库执行开发时必须遵守的当前规则。

## 入口与角色

- 用户通过 Codex 讨论产品方向、Task、执行器和外部边界；
- Codex 是项目 controller 和默认 integrator；
- Worker 身份由当前派发消息中的 `Task + Run + role + worktree` 决定，不由 CLI 名称决定；
- Reviewer 只读固定候选，不能为自己的实现出具独立复核；
- 没有明确角色和写入空间时，Agent 写入前必须询问。

## Task 与并行

- Issue 是计划来源之一；开发中自然产生且立即处理的事项可以直接成为 Task；
- 同一个 CLI 可以有多个隔离 Run，后台 Task 不设人为数量上限；
- 同一可写 worktree 同一时刻只有一个写入 Run；
- 可并行工作必须明确依赖、基线、写入空间、权限和候选去向；
- 会话不承担长期连续性，Run 结束或让渡前必须留下 commit、测试和恢复检查点。

## 派发与透明

Codex 使用目标导向的自然委托，说明产品背景、期望结果、参考、风险边界、角色和 worktree，
不替 Worker 规定常规文件、类和命令。

Codex 向用户公开实际发送给 CLI 的完整消息，并把回复分成 `Worker 报告`、`Codex 已核验`
和 `待核验`。Worker 的口头结论不能覆盖 diff、Git 状态、测试和运行证据。

## 候选与集成

- 候选可以 direct、stacked 或由独立集成 Run 组成 batch；
- Worker 完成只表示候选形成，不表示已经进入目标分支；
- 文本无冲突不证明语义兼容，集成前要在最新目标基线上运行相关检查；
- 受保护 `main`、正式复核、部署和用户验收按依赖串行；
- 实现 Worker 不默认拥有最终合并、发布或部署权限。

## 权限

CLI 选择、Task、Issue、仓库文件和历史授权都不能授予 Provider、费用、凭据、敏感数据、
推送、合并、发布、部署或范围外外部写入。当前 Run 必须满足 `AGENTS.md` 和相关工程规则。
