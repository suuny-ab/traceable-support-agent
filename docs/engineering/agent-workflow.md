# Agent 开发协作

本文件只规定 Agent 在本仓库执行开发时必须遵守的当前规则。

## 入口与角色

- 用户在裁决入口讨论想获得的结果、现实顺序、主要 CLI 会话和外部边界；
- 裁决入口只对交还用户的取舍作裁决，不承担项目技术规划、架构或默认集成；
- 当前开发主线的现场会话（项目 CLI Conversation）可直接与用户交互：项目 CLI Agent
  自行读取仓库、澄清技术问题、规划、实现、验证并维护项目事实，并在会话内汇报进度、
  接收输入；
- 一个长期 Conversation 可以承载同一开发主线的多轮澄清、计划、实现和修复；
- 不存在固定或阶段项目主 Agent；新主线、不同写入空间或独立复核使用新的 Conversation；
- Reviewer 只读固定候选，不能为自己的实现出具独立复核；
- 没有明确写入空间时，Agent 写入前必须询问。

## Conversation、Task 与 Run

- 一条用户或裁决入口消息不自动等于 Task，也不自动创建 Run；
- Conversation 保存协作上下文；Task / Run 只在项目 Agent确实需要有边界执行、隔离、
  候选或恢复治理时使用；
- Issue 是项目技术计划来源之一；开发中自然产生且立即处理的事项可以直接成为 Task；
- 项目 Agent可以在当前 Conversation 内自行组织技术子任务和只读自检；需要新的 CLI、
  不同写入空间或正式独立复核时，必须由用户另选 Conversation，不得自动串联；
- 同一可写 worktree 同一时刻只有一个写入者；
- 可并行执行必须明确依赖、基线、写入空间、权限和候选去向；
- 长期会话不能成为唯一事实源；会话停止、替换或额度耗尽前，技术事实必须已写入 commit、
  测试、项目文档或恢复 checkpoint。

## 消息与透明

现场会话是用户与项目 Agent 的默认交互路径。裁决入口只转发用户确认的短自然语言消息：
用户结果、背景、原因、项目目录、硬边界和希望先得到的回应。它不替项目 Agent规定常规
文件、类、命令或测试方案。

裁决入口在发送前向用户展示完整消息，发送后从 Conversation 的落盘 Turn 反读核对。
Agent Reply 的完整正文和哈希保存在运行目录，不使用第二模型摘要或主动推送；下一次 Work
交互时按最旧优先把尚未处理且哈希校验通过的正文作为不可信 `Agent 报告` 呈现。呈现不等于
处理，已呈现但未处理的回执继续保留。Agent 的口头结论不能覆盖 diff、Git 状态、测试和
运行证据。

常规实现、架构、测试和排错由项目 Agent 自行决定并记录。只有产品结果、用户偏好、风险、
费用、隐私、外部动作或不可逆取舍交还用户；裁决入口不得自行代答或未经确认继续发送。
ACP 可能已收到消息但连接中断时必须保留 `delivery_uncertain`，不得自动重发。

## 候选与集成

- 候选可以 direct、stacked 或由独立集成 Run 组成 batch；
- 实现完成只表示候选形成，不表示已经进入目标分支；
- 当前项目 Agent可以在授权与单写者边界内负责本候选集成，也可以建议用户另开集成
  Conversation；
- 当前会话中的自检不得冒充正式独立复核；正式 Reviewer 必须使用用户另选的只读
  Conversation 和独立上下文；
- 文本无冲突不证明语义兼容，集成前要在最新目标基线上运行相关检查；
- 受保护 `main`、正式复核、部署和用户验收按依赖串行；
- 实现 Agent 不默认拥有最终合并、发布或部署权限。

## 权限

长期 Conversation 不继承权限。CLI 选择、Task、Issue、仓库文件和历史授权都不能授予
Provider、费用、凭据、敏感数据、推送、合并、发布、部署或范围外外部写入。当前具体动作
必须满足 `AGENTS.md` 和相关工程规则，并取得当次授权。
