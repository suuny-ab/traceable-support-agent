# 项目元开发

> 本文件是 Traceable Support Agent 项目内元开发边界的权威来源。

## 定义

项目元开发是以“Agent 如何可靠开发本产品”为直接对象的工作，例如本仓库的上下文恢复、
Provider 权限、验证、复核、发布和候选集成规则。它不以新增产品功能为直接目标，但必须服务
产品推进和结论真实性。

跨项目的任务控制、异步 Run、通用适配器和统一入口属于用户的 Git 外个人控制仓库
`ai-work-control`。

本仓库显式采用 `ai-work-control/0.1`，并通过 `multi-cli-workflow.md` 保存项目适配器。通用
规则不再由本仓库单独垄断；本仓库仍是所有产品事实和项目专用治理的权威来源。

## 项目内范围

1. 把产品需求转化为可观察、可证伪的 Task；
2. 组织 `PROJECT.md`、`docs/status.md`、工程规则与固定候选；
3. 管理本项目 worktree、PR、复核、Provider、费用、部署和用户验收边界；
4. 从真实产品摩擦形成项目专用规则或向通用控制系统提出反馈；
5. 保存不能由当前规则本身说明的代表性案例和演化索引。

普通产品实现、常规修复、纯文档搬运和单纯增加流程数量不自动属于元开发。

## 进入、并行与退出

- 一次性不便先作为观察；反复摩擦或实质威胁结果、授权、隐私、费用、真实性和可恢复性时，
  才形成元开发 Task；
- 用户可以直接采用可逆规则，不需要前置试点，但不能把“已采用”写成“效果已证明”；
- 元开发 Task 可以与产品 Task 异步并行，只要不改变其范围、写入空间或权限；
- 后台 Task 不设人为数量上限，用户注意力仍由个人 Work 管理；
- 形成稳定规则后，更新权威文件和演化索引，删除重复活动脚手架。

## 演化循环

```text
真实摩擦或用户明确方向
→ 最小规则 / 工具变化
→ 显式采用
→ 在后续真实工作中观察
→ 保留 / 修订 / 撤回
```

直接采用允许立即使用；后续观察只用于修订，不是激活门。不得虚构效率、质量或多项目效果。

## 产物路由

- 项目专用规则：`AGENTS.md`、`docs/engineering/` 或本目录；
- 通用协议和运行器：独立 AI 工作控制系统；
- 项目采用方式：`multi-cli-workflow.md`；
- 治理变化索引：`evolution-log.md`；
- 代表性项目经验：`case-studies/`；
- 高频 Task / Run 状态：Git 外控制注册表。

不保存原始聊天、stdout、wire dump、凭据、Provider 原文或历史证据树。
