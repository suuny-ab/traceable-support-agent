## 审计问题

现有治理能够发现真实生产与安全缺陷，但用户等待、复核成本和重复状态维护明显偏高。本次
审计只判断三件事：什么机制确实拦截了缺陷，什么只是调用时机错误，什么可以被自动化或
单一事实所有者替代。

## 可观察样本

时间与 CI 数据来自 GitHub PR / Actions 回执；复核轮次与 findings 来自规范化迁移记录。
“复核轮次”按候选或覆盖 diff 的一次只读检查计数，不把普通主 Agent 自测计入。

| 样本 | 可见周期 | 候选 / PR CI | 已记录复核 | 有效发现与外部结果 |
| --- | ---: | ---: | ---: | --- |

## 观察

### 真正提高质量

- 生产、secret、身份、回滚和公开合同的失败关闭检查阻止了可批准入口上的真实缺陷。
- 变异测试比“存在某段文本”的扫描更有效，能揭示注释、条件、shell 和 YAML 元数据假通过。
- 固定 SHA、不可变清单、受保护 `main` 和服务器正式回执使 CI 成功与生产事实保持可区分。
- 用户实际体验仍是视觉和交互验收的唯一来源，不能被测试或复核替代。

### 主要拖慢推进

- PR #4 在实现仍持续写入时反复做全量复核；每次新 SHA 都使此前的完整结论失效。
- finding 关闭后仍重新扫描未变化区域，复核成本与风险覆盖没有同比增加。
- GitHub Checks、主 Agent 自测与复核者重复检查同一机械合同，职责没有分层。
- 活动事实同时出现在 status、四份工作记录、长案例和 Issue 时，容易重复回写和漂移。
- 评审若在候选合并后才到达，只能作为观察，不能再承担合并门。

### 平台噪声与逃逸缺陷

- PR #4 同一 workflow 两次出现底层 step 已成功但 commit check 长时间未同步；用户手动重试
  一次后通过。这属于 GitHub 状态同步噪声，不应被改写为产品缺陷。
- 生产切换中的 Docker / Caddy 时序只有真实服务器能暴露。它们不是“复核无效”，而是说明
  本地静态复核不能替代生产回执。
- 同 SHA 重跑主线造成的 release identity conflict 证明自动入口需要把“新内容”和“执行
  attempt”分开；不能通过放宽不可变身份门解决。

## 机制裁决

| 机制 | 裁决 | 理由与最便宜替代 |
| --- | --- | --- |
| 单一活动增量 | 保留 | 防止事实与写入并行；允许显式 `ready + 无 active`，不再强制伪工作项 |
| R/S 双轴与外部授权 | 保留 | 直接保护费用、生产、隐私与结论；Issue 和 Git 内容不能授予权限 |
| 四份完整工作记录 | 只服务活动执行 | 完成后产品工作只保留规范化结果与必要复核；元开发提炼规则 / 案例 / 演化索引后删除工作包 |
| 正式独立复核 | 大幅缩门并调整时机 | 只用于高影响门；绿色 Draft PR 冻结 SHA 后一次完整只读复核 |
| finding 后复核 | 合并为针对性复核 | 新 SHA 使旧回执失效，但只检查 finding 与覆盖 diff，不重跑不相关区域 |
| 普通 R0/R1 UI / 缺陷独立复核 | 删除强制门 | 由主 Agent、自动化和浏览器证据关闭；若改变公共合同或公开主张则重新进入正式门 |
| GitHub Issues 与本地待办并存 | 合并为所有权转移 | 未来归 Issue；活动归 status/work；完成归稳定文档与关闭回执 |
| 所有主线提交发布镜像 / 部署 | 删除 | 失败关闭路径分类；明确治理路径不发布、不进入 production；未知路径走完整运行流程 |
| required check 名称随影响变化 | 删除 | `governance/web/api/containers` 始终存在；未受影响任务给出明确成功 |
| GitHub 服务状态作为项目阻断 | 简化 | 记录平台噪声；只有项目步骤失败才修代码，明确授权的单次重跑不改变自动重试 0 |

## 调整后基线

- 正式复核：实现期间 `0`；绿色 Draft PR 后最多 `1` 次完整复核。
- 候选变化：只有 finding 时允许一次或多次有界针对性复核；每次绑定新 SHA。
- GitHub：只管理未来任务、候选 diff、Checks 与外部回执，不复制活动实现事实。
- 仓库：只管理活动事实、稳定产品事实和长期决定。
- CI：明确治理路径目标完成 `<=2` 分钟；不发布镜像、不进入 production environment、不
  运行 SSH。未知路径失败关闭为 `runtime`。
- 产品验证：同一增量完成四页视觉、移动导航、自动化、浏览器、自动部署和用户验收。

## 尚不能形成的结论

本审计本身不能证明新治理更快或同样可靠。后续商业 SaaS 四页重设计完成了绿色 Draft PR、
冻结复核、自动部署、真实浏览器和用户验收，并在减少实施期正式复核的同时关闭了真实
findings，因此本文件中的最小治理变化已经保留。这不证明所有未来任务都会更快；若实际
使用重新出现等待、重复复核或事实漂移，仍须修订。
