# 元开发原则

1. 产品价值是治理存在的原因，不是治理的副产品。
2. 必须能通过一条简短、成文的启动路径重建当前事实。
3. 候选质量与执行完整性是两类不同的失败。
4. 公开主张必须绑定代码、测试或运行证据，并明确限制。
5. 每个工作树只允许一个写入者；独立复核读取固定候选。
6. 外部风险、工程复杂度和产品成熟度是三条独立轴线。
7. 私有证据用于保护结论完整性，不是默认开发数据集。
8. 治理规则默认经过真实产品验证；用户可以明确直接采用可逆规则，后续按实际问题修订。
9. 当前树只保留权威规则、必要证据和代表性案例，过程脚手架交给 Git 历史。
10. 共享规则定义项目边界，派发消息定义会话角色；Worker 拥有执行文档和技术自主性。
11. Codex 逐字公开发给 Worker 的消息，并向用户摘要转述 Worker 的每次回复。
12. 长期连续性属于 Work Object 与 Task；会话是可替换的 Run，结束时留下检查点。
13. 后台 Task 不设人为数量上限；依赖、单 worktree 单写入者、权限和 Delivery 决定并行边界。
14. Issue 是计划来源之一，自然产生且立即执行的工作可以直接成为 Task。
15. 跨项目协议由独立控制系统版本化；项目只通过显式适配器采用，不自动同步或升级。
