# Stage 12 全新未见正式评测规格

> 状态：`completed`
>
> 活动入口：GitHub Issue [#12](https://github.com/suuny-ab/traceable-support-agent/issues/12)
>
> 复杂度：完整路径
>
> 风险 / 成熟度：文档与 runner 实现 `R0`；未见集起草 `R0`（私有、无网络）；生产主机执行
> `R1`（仅合成数据、固定 Provider、调用 / 费用封顶、无业务写入）；目标产出 `S3 正式` 证据

## 用户可见结果

为冻结候选执行一次全新未见 Stage 12 正式评测，产出绑定候选 SHA / 镜像摘要 / 模型 /
prompt 哈希的正式回执：产品自己宣称的不变量（可追溯、失败关闭、人工最终决定、费用
信封）在未见输入上是否成立，以及候选生成类案例的机械观测分数。失败案例如实公开，
为 `product/0.1.0`（Issue #14）提供可判断的证据。

## 要消除的关键未知

- 两阶段 QA / 工单主链在真实 Provider、全新未见输入上是否仍满足不变量。
- 候选生成类案例的来源绑定与逐字事实覆盖在未见输入上的观测水平。
- 评测信封（调用 / 费用上限、重试 0、失败即停）能否在真实执行中保持。

## 最便宜的证伪方法

1. 冻结校验器先证明未见集全部期望可从语料原文逐字追溯（0 Provider 调用）。
2. 注入式离线传输跑通执行与评分管线（0 Provider 调用）。
3. 任一证伪失败则不进入授权执行阶段。

## 测量定位与判定标准

本项目为求职作品集，知识与题目均为合成、无外部业务标尺，因此**不设任意数值阈值、
不做"通过 / 阻止发布"判决**。Stage 12 是诚实测量：价值在测量方法（未见集、冻结候选、
语料可追溯机械核对、失败如实公开），而非达到某个数字。`0.1.0` 是否发布由用户在
Issue #14 依据本证据单独判断，不由本增量机械阻断。

- **不变量验证（二元，对应产品身份主张）**：可追溯（来源绑定）、失败关闭（证据不足 /
  安全 / 越界正确转人工）、人工最终决定、费用信封合规。任一不成立 = 产品缺陷，记录、
  修复后重跑验证；这不是发布闸门，而是主张核查。
- **质量维度（描述性，无阈值）**：候选生成类案例逐例报告机械观测（来源章节匹配、
  `required_facts` 逐字覆盖、结构合同、category / priority），聚合报告观测分数与每个
  失败案例及失败码，如实呈现，不四舍五入为"通过"。
- **期望的语料可追溯性（冻结时强制）**：每个案例的 `required_facts` 必须是其所绑定
  `source_sections` 语料原文中的逐字片段（精确口径：NFKC 归一化 + 去空白后逐字包含，
  与检索分块和运行时机械门同口径），`source_sections` 必须存在于
  `data/knowledge/`。由冻结校验器机械验证——期望不依赖编写者的记忆或品味。
- **单案例机械判定**：结构合同通过（运行时已失败关闭）∧ 引用来源章节 = 期望集合 ∧
  全部 `required_facts` 逐字出现在客户可见正文 ∧ outcome / 转人工失败码正确（工单
  案例另含 category / priority）。
- **明确不评**：流畅度、措辞优劣等开放语义质量——没有可信裁判，列入"不允许形成的
  结论"。不引入 LLM 评审（额外费用且本身未经审计）。
- 配套修订：`docs/engineering/evaluation.md` 末行"已声明业务质量门全部通过才发布
  `0.1.0`"的表述与本定位冲突，收口时修订为"Stage 12 证据 + 用户判断"。

- **问题**：冻结候选在 ≤24 个全新未见合成案例上的不变量成立性与机械质量观测。

- **样本**：24 个全新合成案例（8 维度 × 3），ID 前缀 `STG12-`，私有保管于仓库外，

  web `@sha256:5dccd214fa357a2f69908ac857d5c12112bbbb50d628f2854854a502b293097e`
  （Stage 12 执行的 `live` target 镜像从同一 SHA 构建，摘要执行时记录）；模型 =
  DeepSeek `MODEL`（`api/src/traceable_support/provider/contract.py` 固定，
  `tg07a-deepseek-chat-request-v1`）；prompt 集合 SHA-256
  `dccfa22698af9da6c6af9454a8c7e7ba9b4c193396b8801bf6e81be68189a293`；知识清单

  `replay_only`。
- **重复次数**：全量 1 次；失败案例允许在信封余量内重跑并标注。

- **允许结论**：冻结候选在该未见集上的不变量成立性与机械质量观测。
- **不允许结论**：开放域质量、语义质量、真实客户表现、生产级并发 / SLA、公开实时
  Provider 就绪度。

## 完成门

- runner 与冻结校验器合入 main，PR 四项 Checks 全绿，候选 SHA 与镜像摘要固定。
- 未见集经冻结校验器验证并记录 SHA-256；离线预检 0 Provider 调用通过。
- 用户显式批准授权信封后执行；执行回执显示总调用 ≤150、机制记账费用 ≤¥10、重试 0。
- 正式回执绑定候选身份并如实呈现逐例结果；聚合报告不含明文与 Provider 原文。
- 冻结 head SHA 后一次正式只读复核完成，findings 关闭。
- 稳定文档回写一致（含 `evaluation.md` 定位修订），工作记录归档，Issue #12 按生命周期
  关闭。

## 停止条件

- 授权信封未获用户显式批准：不构建、不传输、不执行。
- 执行中授权、传输、预算、身份或包完整性失败：立即停止，不自动重试。
- 治理 / 评测基础设施开始大于评测目的本身时，停止扩张并说明必要性。
