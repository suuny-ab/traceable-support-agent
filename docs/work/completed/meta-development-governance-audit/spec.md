# 元开发治理审计与商业 SaaS 重设计规格

> 状态：`completed`
>
> 活动入口：GitHub Issue [#7](https://github.com/suuny-ab/traceable-support-agent/issues/7)
>
> 复杂度：完整路径
>
> 风险 / 成熟度：本地实现 `R0`；GitHub 写入与公开部署 `R2`；产品保持 `S1 公开 Beta`

## 用户可见结果

在不改变四个公共 API、回放数据、人工决定语义、Provider 开关或外部动作边界的前提下，
把公开体验重设计为明亮、业务买家优先的商业 SaaS，并证明开发治理可以显著减少等待而不
降低质量。

## 要消除的关键未知

- 独立复核是否因为调用过早、候选持续变化和重复全量复核而浪费成本。
- GitHub 与仓库文件是否因任务所有权重叠造成重复维护。
- 文档 / 元开发提交是否会无必要地构建镜像、读取生产凭据或访问服务器。
- 缩小正式复核门后，自动化、主 Agent 与一次冻结候选复核能否继续拦截真实阻断。
- 当前四页体验能否在保持产品边界的同时达到业务买家可理解、可操作的公开展示质量。

## 最便宜的证伪方法

1. 抽样 PR #4、#8/#9、#10/#11，量化复核轮次、候选失效、CI 噪声、有效 findings、
   文档重复和逃逸缺陷。
2. 用路径分类单元测试和工作流合同测试证明未知路径失败关闭到 `runtime`。
3. 用一个绿色 Draft PR 的固定 head SHA 执行恰好一次完整只读复核。
4. 用同一增量的 Web 重设计验证产品测试、浏览器断点、完整 CI、自动部署和用户验收。
5. 用户验收后的收口 PR 必须被识别为 `governance_only`，并证明不发布镜像、不进入
   production environment、不连接服务器。

## 范围内

- #7 统一裁决 #5（独立复核）和 #6（GitHub / 本地事实边界）。
- 最近发布增量的有界治理审计与已知文档漂移修正。
- 最小正式复核门、冻结候选回执和针对性复核规则。
- GitHub Issue 表单、简短 PR 模板、标签和任务生命周期。
- 路线图中的未启动事项转为 GitHub Issue，路线图只保留结果顺序和链接。
- 失败关闭的 CI 影响分类、四个稳定 required checks、不可变 `release-decision` 和部署预检。
- `/`、`/design`、`/app`、`/privacy` 及共享导航的完整明亮商业 SaaS 重设计。
- 移动导航、键盘、触控、减少动态效果、对比度、无横向溢出和现有产品语义验证。
- Draft PR、固定 SHA 正式复核、自动生产部署、服务器回执与用户验收。

## 范围外

- GitHub Projects、CODEOWNERS、新的用户审批或额外 OAuth scope。
- Stage 12、Provider 调用、费用、API 改造、域名购买、旧仓删除或生产级高可用。
- 远程字体、视频或重型视觉依赖。
- 自动发送、退款、换新、结单或其他外部业务动作。
- 从一次未经验证的观察直接提取通用模板。

## 治理候选

- 未来任务归 GitHub Issue；启动后由 `docs/status.md` 与唯一活动工作接管；PR 绑定候选、
  Checks 和部署回执；Agent 在所需验收齐全后回写稳定文档并关闭 Issue。
- PR 不使用自动关闭关键字。Issue 的关闭是完成回执，不是合并副作用。
- 正式复核只用于元规则、S2/S3、生产 / 发布、安全、隐私、认证、费用、持久化、公共合同
  或公开主张变化。普通 R0/R1 UI 与缺陷修复由自动化和主 Agent 关闭。
- 正式复核只在 Draft PR 全绿后冻结 head SHA 并停止写入时调用；复核者只读。
- 候选变化使旧回执失效，但默认只复核原 finding 和覆盖 diff；没有 finding 不产生第二轮。
- 单个 worktree 始终只有一个写入者。

## 产品合同

- 首页优先解释业务价值、失败转人工和可追溯决定。
- 设计页承载架构、失败关闭和工程证据。
- 工作台首屏以输入、轨迹、证据和决定为核心。
- 隐私页集中呈现合成数据、Provider、留存和外部动作边界。
- 导航提供真实 GitHub 仓库链接和可键盘操作的移动菜单。
- 全站使用暖白背景、深海军蓝文本、品牌蓝 / 青绿主色和琥珀警示色。

## 完成门

- 历史审计和文档漂移修正有规范化证据。
- GitHub 生命周期、标签、Issue 表单和路线 Issue 已落地。
- 分类器与工作流失败关闭测试覆盖治理类、运行类、未知路径和缺失 decision。
- 运行类视觉 PR 通过本地检查、四个 GitHub Checks、一次冻结候选复核和自动部署。
- 桌面 `1440×900`、平板 `1024×768`、手机 `390×844` 的四页与关键交互通过。
- 正式部署回执绑定新 SHA；两个容器健康；公网五路由为 `200`；保持
  `provider_enabled=false`、`replay_only`。
- 实施期间零正式复核；绿色 Draft PR 后最多一次完整复核；只有 finding 才允许针对性复核。
- 用户无需操作 GitHub 或生产批准；用户实际体验后完成验收。
- 收口 PR 的治理类路径从 runner 启动到完成目标不超过 2 分钟，且不发布、不进入
  production environment、不执行 SSH。
- 不留下 P0–P2 阻断或错误公开主张。

## 停止条件

- 路径无法可靠分类时回退为 `runtime` 完整流程，不允许为了提速误跳过。
- 线上视觉或用户验收未通过时保持 #7 活动，在同一增量修复。
- 任何 Provider、费用、敏感数据或外部业务动作需求立即停止并另行授权。
- 完成最小治理变化和一次真实产品验证后立即收口，不扩张为通用模板工程。
