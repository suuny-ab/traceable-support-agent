# 工作记录

需要跨会话持久化、隔离候选或恢复治理时，标准和完整增量可以存放在
`active/<slug>/`；不因规模标签默认创建目录。创建后，每个增量包含四个短文件：

- `spec.md`：开工三问、风险 / 成熟度和验收条件；完整工作或触及部署、费用、安全边界、
  `R2` 时补齐证伪方法、复用资产、投入 / 停止线和允许结论；
- `plan.md`：有顺序的实施步骤与停止条件；
- `result.md`：实际交付和验证结果，不记录仅仅预期的主张；
- `review.md`：机器检查、证据边界、所需当次授权，以及触发时的只读评审记录。

允许多个独立产品结果目录在不同工作树中并行；每个目录仍必须由 `docs/status.md` 链接，
且同一工作树只有一个写入 Run。代码、机器检查、所需当次授权、触发的方案级疑问和事实
更新全部关闭后，才把对应目录移入 `completed/`；已完成工作不能授权新的改动。轻量工作
只需回答开工三问，在 Conversation、PR 或受影响的当前文档中留下必要结果，并形成一个
边界清楚的提交。

Task 和 Run 的高频状态位于 Git 外控制注册表，不为每个会话复制四文件目录。一个标准 /
完整产品结果目录可以承载多个相关 Task。`docs/status.md` 的 `state` 表示进度，不触发目录
数量要求；没有活动目录也可以诚实记录正在形成的轻量或标准候选。

Git 只记录技术收口。授权默认值的唯一正文见
[`review.md`](../engineering/review.md#授权层唯一默认值正文)。
