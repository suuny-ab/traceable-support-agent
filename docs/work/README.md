# 工作记录

标准和完整增量存放在 `active/<slug>/`，每个增量包含四个短文件：

- `spec.md`：用户可见结果、范围、风险 / 成熟度和验收条件；
- `plan.md`：有顺序的实施步骤与停止条件；
- `result.md`：实际交付和验证结果，不记录仅仅预期的主张；
- `review.md`：独立固定快照复核及其收口结论。

允许多个独立产品结果目录在不同工作树中并行；每个目录仍必须由 `docs/status.md` 链接，
且同一工作树只有一个写入 Run。代码、验证、复核和事实更新全部关闭后，才把对应目录移入
`completed/`；已完成工作不能授权新的改动。轻量 Task 只需在受影响的当前文档中留下简洁
结果，并形成一个边界清楚的提交。

Task 和 Run 的高频状态位于 Git 外控制注册表，不为每个会话复制四文件目录。一个标准 /
完整产品结果目录可以承载多个相关 Task。

Git 只记录技术收口。GitHub 公开发布、生产部署、用户验收和破坏性清理仍是独立检查点，不能从任何被跟踪文件中推断已经获准。
