1. 把首页 v4 明确为产品载体，把“Codex 唯一入口、用户选择 Worker、Codex 派发与集成”
   明确为主要元开发假设；实验通过前不建立长期规则。
2. 核对现有 v1–v3、对齐页、K3 视觉分析和工作记录，运行最快相关检查，形成可恢复的
   checkpoint commit。
3. Codex 输出首张 CLI 状态卡：核实安装、认证、模型、额度可见性、当前运行任务和写入
   可用性；不能读取的额度保持 `待确认`。
4. 等待用户明确选择首页 v4 Worker；选择前不启动新的外部 CLI 写入任务。
5. 若用户选择 K3，从 checkpoint 创建独立 worker 分支 / worktree，固定允许路径、基准
   SHA、唯一写入者、会话和停止条件；Codex 留在集成 worktree。
6. Worker 负责实现、运行页面、录屏、专业自验与候选提交；Codex 同时只推进不重叠的
   响应式、可访问性、性能、状态和集成工作，不重做视频判断。
7. Worker 返回短交接回执；Codex 检查范围、diff 和工程证据后集成，再由专业 Worker 检查
   集成后的动态页面，最后由用户体验验收。
8. 记录墙钟时间、可获得的额度信息、冲突、重复工作和协调成本，裁决工作流
   `保留 / 修订 / 撤回`。
9. 只有裁决保留后，才新增长期决定并在 `AGENTS.md` 放置简短路由；元规则候选在固定 SHA
   上按正式复核门处理。
