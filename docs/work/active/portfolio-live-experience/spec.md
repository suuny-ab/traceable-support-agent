## 本轮主要目标

本轮产品目标仍是完成 Issue #28 的最终作品集视觉与三个固定示例的受控真实体验。当前先
保留已经形成的首屏参考对齐 checkpoint，不预设下一步一定实现首页 v4；在当前长期项目
Conversation 或用户明确选择的替代 Conversation 中，先确认一个可独立验收的任务范围。

## 用户结果

招聘方进入公开网站后，首先看到一个专业、有记忆点、能准确表达产品定位的主页；随后可以
从三个固定合成示例中选择一个，亲自触发新的受控运行，并看见证据如何经过检索、义务规划、
生成和机械校验形成 `candidate` 或 `handoff`。

当前设计阶段先消除三个关键未知：

1. 主页首屏怎样在几秒内建立产品定位与专业感；
2. 首页、工作台和工程证据分别应该承担哪些信息；
3. 页面用什么具体文字表达产品，避免通用 AI 营销语气和信息堆叠。

用户已经确认主页结构 v1 和产品命题“让每一条客服回复，都能回到它的依据。”。v1 把来源、
绑定和回复文字塞进透镜，过程追踪喧宾夺主；v2 又改成静态短品牌椭圆、短定位和四个流程
标签，视觉与产品解释均过度简化。两版都未通过。当前 v3 恢复原定位句，使用持续滚动的
`TRACEABLE` 品牌字带、圆形压缩折射和月牙高光，并用一个具体示例讲完整运行来路；用户仍
判断文字方向、动态效果和页面布局与预期差距明显。v3 未通过，当前停止实现并回到可测量的
参考对齐；最终视觉仍未冻结。

## 已确定的设计方向

- 主页负责产品定位与第一印象，工作台负责证明产品真实存在，工程证据页负责经得起面试追问。
- 主页第一屏参考 Moonshot 当前首屏的构图、留白、节奏和沉浸动态；第一屏之后与其他页面
  按各自任务采用合适的信息密度，不全站复制大留白。
- 首屏动态采用原创实现的 `Evidence Lens / 证据透镜`：重复 `TRACEABLE` 字带持续横向
  滚动，在中央圆形透镜中被压缩折射，月牙高光提供唯一视觉焦点；透镜不再承载来源、绑定、
  回复或检查文字。不复制 Moonshot 的源码、素材或品牌图形。
- 首屏动效只承担品牌表达，不伪装实时运行；工作台阶段动效只能由服务端持久化的真实状态驱动。
- 保留 Issue #28 的语义配色规则：证据为青色、`candidate` 为绿色、`handoff` 为红/橙；
  当前不冻结具体色值、字体、材质、阴影或动效参数。
- 首页文案使用具体、自然、可验证的表达，减少 `AI`、`LLM`、`Agent Workflow`、赋能、
  智能、可信等堆叠；技术术语进入工作台或工程证据页。
- 公开入口只提供三个不可编辑示例，不把主页或工作台表现成自由聊天。

## 前端设计合同 v1

### 设计目标

主页先建立产品定位与专业感，让招聘方愿意继续体验；工作台证明这不是静态概念页；工程证据
页让系统边界和实现经得起追问。

最终前端不追求“像一个 AI 网站”，而要像一件完成度高、可以亲手操作、能够解释结果来源的
工程产品。

### 主页首屏

- 只参考 Moonshot 当前首屏的构图、留白、节奏和沉浸动态；
- 接近一整屏高度，只保留品牌、极简导航、产品定位和继续浏览的节奏；
- 不放能力卡、版本治理、Provider 状态、技术参数、按钮组或长解释；
- 第一屏之后不强迫全站使用大留白；后续内容和其他页面按任务选择密度。

### 原创动态

名称暂定 `Evidence Lens / 证据透镜`：

- 透镜外是尚未核对的来源、回复片段和状态；
- 片段经过透镜后显现来源 clause、回复片段与检查关系；
- 不能建立来源的片段停止、离开或保持不可确认；
- 动效只承担品牌叙事，绝不显示伪造的 run 阶段或虚假进度；
- 不复制 Moonshot 的月食图形、品牌文字、素材、代码或 Shader；
- 文案保持为可访问 HTML，并支持静态关键帧、`prefers-reduced-motion`、离屏暂停和手机降级；
- 动效加载失败时产品定位仍完整可读。

### 研究后的信息架构

1. 主页：产品定位、一个代表性运行预览、两种结果、工程边界与体验入口；
2. 工作台：三个固定示例、启动或恢复 run、真实轨迹、终态结果、来源与人工决定；
3. 工程证据：架构、信任边界、失败关闭、评测、API 与 GitHub；
4. 隐私与运行边界：保留独立内容，但是否继续作为一级导航待高保真阶段确认。

研究使主页从“三个示例陈列”收敛为“一个代表性 run 证明定位”。手机端必须重新编排图形、
文字、行动与结果顺序，不能等比压缩桌面布局。

### 文字原则

- 先说对象、动作和结果，再说技术名词；
- 一句话只承担一个事实；
- 避免空泛的“赋能、智能、领先、可信、重塑”和连续对偶口号；
- 首页不反复出现 `AI`、`LLM`、`Agent Workflow`；
- `LIVE MODEL`、`VERIFIED REPLAY`、`HANDOFF` 只在需要区分运行身份时使用；
- 已知限制写清楚，但不让版本、治理和风险术语占据品牌首屏。

### 语义配色

只冻结角色，不冻结样式：

- 证据：青色；
- `candidate`：绿色；
- `handoff`：红 / 橙；
- 中性状态、品牌背景、具体色值和材质：待最小原型与高保真阶段决定。

## 主页结构稿 v1

### 导航

桌面：

```text
Traceable Support Agent        产品原理   工程证据   GitHub        [查看运行]
```

手机：

```text
Traceable Support Agent                                      [菜单]
```

不在导航常驻显示 `Provider disabled`、`公开回放在线` 或版本状态；隐私与运行边界保留在
工作台上下文和页脚。

### 品牌首屏

```text
┌──────────────────────────────────────────────────────────────┐
│ 导航                                                         │
│                                                              │
│              [Evidence Lens 原创动态主视觉]                  │
│                                                              │
│             让每一条客服回复，                               │
│             都能回到它的依据。                               │
│                                                              │
│                         ↓                                    │
│           查看一条回复如何形成  →   （下屏轻微露出）         │
└──────────────────────────────────────────────────────────────┘
```

手机端保留品牌、定位和入口；降低 Canvas 元素数量与文字带密度，必要时使用静态关键帧。

### 一次运行的来路

标题初稿：

> 一次运行，保留问题、来源、检查和决定。

使用一个明确标记的公开合成回放作为产品证明：

```text
客户问题
CZ-R1 怎么开始局部清扫？

       01 来源              02 处理要求
       KB-CZR1-014          操作条件 / 动作 / 限制
              \             /
               03 客户回复
               将设备放到需要清扫的区域……
                       |
               04 检查与决定
               来源通过 · 等待人工确认
```

来源 clause、回复片段和检查关系是视觉主线；标记 `VERIFIED REPLAY`；主页不提供完整人工
决定操作，主要行动为“在工作台查看完整运行”。

### 两种诚实结果

标题初稿：

> 系统只交付两种结果。

```text
CANDIDATE
证据和检查通过，形成等待人工确认的回复或工单建议。

HANDOFF
证据不足、范围冲突或运行异常，停止并说明原因。
```

三个固定示例不在主页陈列，全部进入工作台。

### 运行边界

标题初稿：

> 模型不决定来源、预算或重试。

```text
来源       客户可见事实绑定批准的 clause
调用       单次运行最多 2 次模型调用
重试       自动重试 0
业务动作   人工决定只被记录，不自动发送、退款或结单
```

API、队列、日 / 月预算、留存、评测和版本状态不在主页展开。

### 进入产品

标题初稿：

> 亲自查看一次完整运行。

```text
[进入工作台]    [阅读工程证据]
```

页脚保留合成数据、零自动业务动作、隐私与运行边界、GitHub 和当前发布语义。

## 首页与工作台文案

### 已确认产品命题、待确认首屏表达

> 让每一条客服回复，<br>
> 都能回到它的依据。

它直接说明客服产品类别，并让“回到依据”与 `Evidence Lens`、来源回读形成同一命题。

v2 曾把首屏缩短为：

```text
TRACEABLE

客服回复，有据可查。
```

用户判断短定位不如原定位句，且静态 `TRACEABLE` 没有复现参考站的滚动文字效果，因此 v2
未通过。v3 恢复本节开头的两行产品命题，并让 `TRACEABLE` 只存在于动态字带和导航品牌中。

备选：

> 每一条客服回复，<br>
> 都应该有据可查。

备选更简洁，但容易被理解成普通知识库检索，弱化生成、检查和停止机制。

不采用：

- “让每个 LLM 结论都有证据”：技术味较重，保留为内部产品命题；
- “让客服 AI 的结论有证据，能退出”：对偶口号感和 AI 味明显；
- “可追溯客服决策支持 Workflow”：准确但像架构名；
- “把模型放进一条可检查、可停止的业务链”：进入工程证据页。

工作台首要文案：

```text
选择一个公开合成示例

[QA · 局部清扫]
[TICKET · 地毯风险]
[HANDOFF · 证据不足]

这次运行会创建新的 run。最多 2 次模型调用，自动重试 0。
```

实时不可用时只明确说明不能创建新的运行，并提供“查看已验证回放”；禁止“智能生成中”
或“AI 正在思考”等虚假拟人文案。

## 手机顺序

主页：

```text
品牌 → Evidence Lens 降级 → 定位 → 运行入口
→ 问题 → 来源 → 回复 → 检查
→ Candidate / Handoff → 运行边界 → CTA
```

工作台：

```text
运行身份 → 选择示例 → 主要行动 → 真实阶段轨迹 → 终态
→ 客户可见结果 → 来源 / 义务 / 门 → 人工决定
```

## 最小原型合同

`Evidence Lens` 原型只回答：

1. 透镜能否表达“核对前模糊、核对后可追溯”；
2. 动画是否原创且没有通用 AI 粒子感；
3. 定位文字是否始终可读；
4. 桌面是否稳定流畅；
5. 手机降级与 `prefers-reduced-motion` 是否完整；
6. 动效失败是否仍保留可用首屏。

原型不连接 Provider、运行接口或生产数据。

原型实现固定为独立静态页面：

- 使用原生 Canvas 2D，不增加依赖，不注册 Next.js 生产路由；
- Canvas 只滚动绘制产品名，不绘制解释性文字；
- 桌面与手机都保留圆形压缩折射和月牙高光，手机降低字带尺寸；
- `prefers-reduced-motion` 显示静态关键帧，渲染不可用时显示 HTML 降级；
- 离屏与页面不可见时暂停，回到首屏后恢复；
- 当前中性深色背景与语义色只服务原型辨识，不构成最终配色、字体或材质决定。

## 首屏视觉对齐合同 v0.1

对齐稿位于 `web/prototypes/evidence-lens/alignment.html`。它只冻结参考站当前首屏的可见
位置、比例和运动方向，不复制源码、品牌资产或生产内容。

### 桌面 `1280 × 720`

- 导航：高 `72px`；
- 动态画布：`x 0 / y 144.5 / 1276 × 400`；
- 品牌字带：向右连续循环；500 ms 双帧位移约 `43px`，即约 `86px/s`；
- 透镜核心：直径约 `216px`，暗侧接近背景，只让一段月牙高光成为焦点；
- 定位句：`y 518.3`，桌面单行；
- 入口面板：`x 268.3 / y 605 / 739.5 × 139.3`。

### 手机 `390 × 844`

- 导航：高 `72px`；

## 本轮任务：live 主路径工作台（2026-07-24 · Worker Kimi K3）

> 文档；不触碰产品 Provider、凭据、生产开关、部署与外部写入。

### 任务理解

公开工作台从“回放为主”改为“真实 LLM 新 run 为主路径”：

1. 三个有公开合成来源的默认案例（QA：CZ-R1 局部清扫；工单：CZ-R2 长毛地毯；故障处理：
   CZ-R2 基站 E310 集尘通道受阻），每次点击都 POST `/api/v1/runs` 创建新的 run；
2. 受约束自由探索：500 字自由输入 + 型号选择 + 推荐问法，仍由既有敏感内容预检、
   范围词表、队列 / 预算 / 浏览器软限约束在虚构 CZ-R1/CZ-R2 沙箱内；
3. `GEN-DEV-IE-001` 作为边界挑战：同样创建真实新 run，但在批准资料不足时于 Provider
   调用前 handoff，`provider_call_count=0`，不绕过停止门；
4. 面试官可见：真实服务端阶段（queued→retrieving→planning→generating→validating→终态）、
   客户可见结果、clause 级来源绑定、机械门、已知时显示 Provider 调用次数、
   `handoff_reason`，以及人工批准 / 编辑 / 拒绝；
5. 禁止 Chain of Thought 与伪造的“模型思考”动画；实时失败 / 不可用 / 状态未知时诚实
   呈现，绝不用回放冒充本次运行。

### 关键实现判断（调研后）

- 后端 live 链完整存在（`DefaultProductRunner` + 两阶段生成 + 投影 + 持久化），缺的只是
  公网装配点：`http.py main()` 永远不传 `product_runner`。本轮新增 env 门控装配
  （默认关，生产 compose / Dockerfile 不改）。
- `GEN-DEV-IE-001` 的 0 调用 handoff 当前无实现：该输入会穿过预检进入真实检索与 2 次
  Provider 调用。本轮在 `product/boundaries.py` 增加 `unsupported_claim` 确定性规则
  （无线网络频段能力不在批准来源内），经 preflight → `_insert_blocked_run` 形成新 run、
  0 调用、不存原文；runner 与 `run_qa` / `run_ticket` 内层自动获得同一拦截。回放预设
  `qa-insufficient-evidence` 的 note（“实时链尚未实现同一拦截”）同步失效并更新。
- 第三个默认案例（E310）知识已就绪（`FAULT-CODES/r2-e310-dust-bag`），无已验证回放；
  live 不可用时该案例只显示“无可用回放”，不伪造。
- 回放降级为显式次要入口：只有用户主动点击才查看已验证回放，并始终标记
  `VERIFIED REPLAY`；案例点击不再自动路由到回放。
- 隐私边界评估：自由输入面不扩大（同一 500 字上限、同一敏感预检、同一 30 天保留），
  不构成新的隐私 / 安全边界变化，无需停止升级。

### 可观察结果（验收标准）

1. 工作台信息层级：运行身份（live 状态检测）→ 三个默认案例 + 一个边界挑战 → 受约束
   自由探索（推荐问法）→ 已验证回放次要入口。
2. live 可用时：点击任一案例创建新 run，阶段轨迹来自服务端状态轮询；终态显示
   run id、`LIVE MODEL` / handoff 身份、Provider 调用次数（0 / 2 / 未知）、
   `handoff_reason`、来源 clause、机械门；candidate 可批准 / 编辑 / 拒绝并写入服务端。
3. 边界挑战创建新 run 并在 Provider 调用前 handoff，`provider_call_count=0`。
4. live 不可用 / 未知：普通案例与自由探索不创建新运行，明示原因与“重新检测”；固定边界挑战
   例外——仍可创建 0 次模型调用的确定性转人工运行；提供查看已验证回放。公开说明（主页、
   工作台状态行、案例卡）必须与该合同一致，不得笼统声称“不能创建新运行”。
5. 实时超时 / 断连 / 协议错误 / 503：诚实 handoff 文案，不自动重试，可继续查询同一 run。
6. 生产事实不变：`provider_enabled=false`、`replay_only`、无凭据、无部署。
