# Stage 12 失败根因归类

## Goal

在不重跑评测、不修改代码的前提下，对 `2026-08-02` Stage 12 修复后首次复验的全部失败码
做结构化根因归类，给出每类一个最小修复候选与停止线，使下一轮工作能先拆最可能的门，
而不是继续凭总通过数猜测。

## Non-goals

- 不修改产品代码、runner、评分器、prompt、评测集、知识、公开回归案例或 Workflow。
- 不再次调用 Provider，不重跑或补跑 Stage 12，不改变 `24/24、2 通过`的既有观测。
- 不公开私有输入、冻结期望事实、来源章节 ID、Provider 原文、凭据或环境清单。
- 不把结构化归因写成已证明的因果效果，不承诺任一候选能提高全合同通过数。
- 不转 Ready、不合并 `main`、不部署、不发布 `product/0.1.0`。

## AC

1. **WHEN** 核对公开聚合，**THEN** 全部失败码按 `case_id + failure_code` 唯一归入一个根因，
   没有漏项、重复项或不存在的分配。
2. **WHEN** 解释派发口径，**THEN** 明确“其他 1”是一个案例同时产生两个字段码，因而派发
   的 36 个分组信号对应机器聚合中的 37 个失败码出现次数。
3. **WHEN** 分析 `required_fact_missing`，**THEN** 分开检索未召回、义务规划遗漏、生成表达
   与字面评分合同，不用一个总码代替阶段定位。
4. **WHEN** 分析 `outcome_mismatch` 与来源不匹配，**THEN** 分开产品边界覆盖、生成合同失败、
   handoff 评分合同和额外来源，不把派生失败码重复算作独立根因。
5. **WHEN** 报告每个根因，**THEN** 至少给出公开案例 ID、Git 外结构化取样结论、一个最小
   修复候选、复杂度与停止线；不写入私有明文。
6. **WHEN** 给出检索判断，**THEN** 仅陈述本次机械检查能证明的 Top-10 覆盖事实，不外推为
   检索质量、开放域质量或因果结论。
7. **WHEN** 完成交付检查，**THEN** 公开聚合一致性、私有泄漏专项扫描、相关文档 / 治理检查
   与 `git diff --check` 通过，Provider 调用保持 0。
8. **WHEN** 推送候选，**THEN** 只更新既有 `night-20260802` / Draft PR #62 并确认最终 head
   required Checks 全绿；不转 Ready、不合并、不部署。
