# 唯一权威仓库治理迁移规格

> 状态：`active`
> 复杂度：完整路径
> 风险 / 成熟度：本地 `R0`；远程 / 部署 `R2`；产品保持 `S1`

## 用户可见结果

一个公开仓库成为唯一长期开发基础。面试官无需查看原始内部历史就能理解和运行项目；新的开发 Agent 仅依靠该仓库就能恢复相同的产品、安全和元开发边界。

## 范围内

- 干净的 Git 基线和分层 monorepo（单仓）结构。
- 当前产品 / API 行为、标准 Next Web 和回放部署。
- 产品与评测的依赖反转。
- 八个脱敏回归案例和五个元开发案例。
- 以 `docs/meta/README.md` 作为元开发定义的唯一权威来源，保留产品开发与元开发的可判定边界。
- 治理/公开安全 CI、GHCR 镜像和按镜像摘要部署。
- 一个真实的 `GEN-DEV-IE-001` 回放预设增量。
- 面向人的仓库文档以中文为主，代码标识和必要英文技术术语保持原样。

## 范围外

- Stage 12、任何 Provider 调用或费用、公开实时 Provider、`product/0.1.0`、最终视觉重设计、域名购买或生产级高可用。

## 复用审查

- 复用现有公共 API 控制面、Stage 11 产品合同、六份合成知识、方向 B Web、Docker / Caddy 拓扑，以及已复核的预算和留存语义。
- 使用标准 Next 自托管和 GitHub Actions / GHCR，不继续维护 Sites / vinext 或自建镜像仓库。
- 只新增薄的包与部署适配层，不改变检索 / 生成语义。

## 完成门

- 创建任何远程仓库前，公开安全扫描通过。
- 新旧行为 fixture、公共 API、回放 Web 和容器检查通过。
- 冷启动仅依靠唯一权威仓库文件即可回答 `10/10`。
- 全新克隆可以构建、测试和运行。
- 真实的小型回放增量在新协议下完成收口。
- 公开远程仓库和按镜像摘要部署通过；当前服务保持 `replay_only`，Provider 使用量为 0。
- 面向人的 Markdown 文档完成中文化，并通过链接、主张和冷启动复核。
- 新 Agent 能依据仓库区分产品开发与元开发，说明五类范围、非范围、进入/退出边界和验证循环。
- 删除旧仓前，用户认可仓库组织、开发舒适度和公开回放。
