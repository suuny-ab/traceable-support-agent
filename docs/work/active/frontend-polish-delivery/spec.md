# 前端整体打磨公开交付

## 产品价值

把已经通过本地用户验收的四页求职展示候选交付到公网，让招聘方实际看到更清楚的首页、
引导式工作台、工程证据和隐私边界；本工作不继续增加功能或审美微调。

## 开工三问

- 做什么：推送 `codex/frontend-polish`，以 PR #52 通过必需检查后 squash merge 到受保护
  `main`，等待既有自动部署，并核对公网健康完整 SHA 与四个公开页面。
- 不做什么：不修改后端、RAG、Provider、数据、安全合同或评测结论；不调用真实 Provider，
  不运行公网案例，不处理 `product/0.1.0`、独立域名、布局字体微调或未跟踪 `clean/`。
- 怎样算完成：PR 的 governance、web、api、containers 在同一候选 SHA 上全绿；squash
  merge 成功；自动部署成功；公网健康 `release_sha` 与合并 SHA 精确一致；`/`、
  `/design`、`/app`、`/privacy` 均可达且关键文案属于新候选；状态和工作记录完成归档。

## 授权与外部风险

用户于 `2026-08-01` 明确授权本次推送、合并和部署。授权目标仅为 PR #52 所绑定的已验收
前端候选及完成交付所需的最小治理记录，不授权 Provider 调用、费用扩张、其他仓库写入或
范围外产品变化。外部风险为 `R2`：GitHub 写入、受保护 `main` 合并和生产部署。

## 风险与最便宜证伪

- 候选范围漂移：比较 PR head、变更文件和已验收候选；出现产品范围外文件立即停止。
- CI 绿灯掩盖未执行检查：只接受同一 head 上明确成功的四个 required checks；skipped 或
  missing 不算通过。
- 部署错误版本：由 release manifest、部署健康门和公网 `/api/v1/health.release_sha`
  共同精确核对 squash merge SHA。
- 页面部署退化：部署后只读请求四个路由并核对新版关键文案；不创建产品运行。
- 生产切换失败：沿用既有失败关闭和回滚锚点；失败部署不自动重试。

## 复用、投入与停止线

复用现有受保护分支、CI 证明合同、GHCR 不可变镜像、自动部署、健康 SHA 门和回滚流程，
不新增依赖、服务或 Workflow。若修复需要改变产品行为、Provider、安全边界或扩大公开主张，
立即停止并重新取得用户决定。

本工作完成后只允许形成以下结论：已验收的前端候选已由既有发布链交付到与合并 SHA 绑定的
公网 Beta。它不证明新的模型质量、移动设备覆盖、生产级高可用或 SLA。
